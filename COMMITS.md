# Правила коммитов

В проекте используется [Conventional Commits](https://www.conventionalcommits.org/).

Правила распространяются на весь монорепозиторий: `app/`, `web/`, `contracts/`, `infra/`, `docs/` и другие каталоги.

## Формат сообщения

`type(scope): subject`

Пример:

`feat(web): добавить форму поиска отелей`

Части сообщения:

- `type` — обязательный тип изменения;
- `scope` — необязательная область изменения;
- `subject` — обязательное краткое описание изменения.

## Допустимые типы

| Тип | Когда использовать |
|---|---|
| `feat` | Добавление новой функциональности |
| `fix` | Исправление ошибки |
| `docs` | Изменения в документации |
| `style` | Форматирование без изменения логики |
| `refactor` | Рефакторинг без исправления ошибки или добавления функциональности |
| `perf` | Улучшение производительности |
| `test` | Добавление или изменение тестов |
| `build` | Изменения системы сборки или зависимостей сборки |
| `ci` | Изменения CI/CD |
| `chore` | Рутинные технические изменения |
| `revert` | Отмена предыдущего коммита |

## Правила оформления

- Тип обязателен
- Тип должен быть написан в нижнем регистре
- Scope, если используется, должен быть написан в нижнем регистре
- Описание обязательно
- Описание не должно заканчиваться точкой
- Максимальная длина первой строки — 100 символов
- Описание следует начинать со строчной буквы

Корректные примеры:

```text
feat(web): добавить форму поиска путешествий
fix(app): исправить таймаут поставщика
docs: обновить инструкции по локальной настройке
refactor(app): извлечь общую логику поиска в отдельный класс
test(app): добавить тесты для класса поиска
build(web): обновить зависимости сборки
ci: сконфигурировать GitHub Actions для проверки качества кода
chore: обновить зависимости проекта
```

## Breaking changes

Для изменений, нарушающих обратную совместимость, после типа или scope
используется `!`:

`feat(contracts)!: изменить формат ответа поиска`

## Scope

Scope необязателен. Он должен кратко обозначать область изменения.

Рекомендуемые scope:

| Scope | Область |
|---|---|
| `web` | React-приложение |
| `app` | Java-приложение |
| `contracts` | API-контракты и OpenAPI |
| `infra` | Docker и инфраструктура |
| `docs` | Документация |
| `ci` | GitHub Actions и CI/CD |
| `deps` | Обновление зависимостей |

Примеры:

```text
feat(web): добавить форму поиска путешествий
fix(app): исправить таймаут поставщика
docs(docs): обновить инструкции по локальной настройке
ci(ci): сконфигурировать GitHub Actions для проверки качества кода
chore(deps): обновить зависимости проекта
```

Если изменение затрагивает несколько областей, scope можно не указывать:

`refactor: переорганизовать структуру проекта`
